# Ordo

**Ordo** — планировщик задач со сроками, историей, комментариями и напоминаниями.
Написан на чистой стандартной библиотеке Python (без внешних зависимостей):
хранилище — SQLite, CLI — `argparse`, доставка напоминаний — подключаемые каналы.

Он задуман как первый кирпич системы: сначала навести порядок в собственных
задачах и репозиториях, а затем навесить сверху агентов и автоматизацию.

## Установка

Ничего ставить не обязательно — достаточно Python 3.9+:

```bash
python3 -m ordo --help          # из папки проекта
```

Либо установить команду `ordo` в PATH:

```bash
python3 -m pip install -e .
ordo --help
```

## Быстрый старт

```bash
ordo init                                  # создать БД (ordo.db рядом) и показать пути
ordo project add ordo -d "Планировщик"     # проект
ordo add "Собрать бота" -p ordo -d 3d -P 1 # задача со сроком "через 3 дня", приоритет high
ordo add "Починить парсер" -d 2026-11-30   # абсолютный срок (время берётся из конфига)
ordo list                                  # список: приоритет, срок, «через сколько»
ordo show 1                                # подробно: комментарии, история, напоминания
ordo start 1
ordo comment 1 "начала разбирать API" -k progress
ordo postpone 1 -d 5d -r "жду ответ от сервиса"   # перенос с причиной + напоминание об этом
ordo done 1 -c "готово, проверено"
ordo check                                 # что требует внимания прямо сейчас
ordo remind --dry-run                       # что будет отправлено (без отправки)
ordo remind                                # отправить напоминания
ordo bot --test                             # проверить, что Telegram настроен
ordo bot --once                             # обработать накопившиеся команды бота
ordo bot --follow                           # слушать команды вживую (Ctrl+C — стоп)
```

`ordo` без команды == `ordo check`.

### Форматы сроков (`-d`)

| Ввод | Значение |
|---|---|
| `3d`, `12h`, `30m`, `2w` | относительно сейчас |
| `in 3 days`, `+2w` | то же самое |
| `2026-11-30` | дата, время = `due_time` из конфига (по умолчанию 18:00) |
| `2026-11-30 09:30` | дата и время |
| `tomorrow 07:00`, `today 20:00` | день + время |
| `mon`, `friday` | следующий такой день недели |
| `now` | прямо сейчас |

### Как работает «перенос с напоминанием»

Перенос не просто меняет дату — Ordo:

1. увеличивает счётчик переносов задачи (`postpone_count`) и пишет событие в историю;
2. сохраняет причину как комментарий;
3. пересобирает напоминания под новый срок;
4. ставит отдельное напоминание-догон (`postpone_followup`) через
   `reminders.postpone_recheck` (по умолчанию 1 день), чтобы перенос не забылся.

Просроченные задачи, о которых так и не отчитались, автоматически попадают в
блок `POSTPONED` и `OVERDUE` команды `ordo check`, а также в повторные
напоминания с интервалом `reminders.nag_interval` (по умолчанию 12 ч).

## Напоминания

Напоминания don'т живут в фоне сами по себе — их запускает команда `ordo remind`.
Так сделано намеренно: прозрачно, тестируемо и одинаково хорошо работает из cron,
systemd-таймера или (позже) из Telegram-бота.

Что отправляется:

| Тип | Когда |
|---|---|
| `due_soon` | за `reminders.before` (по умолчанию 1 день) до срока |
| `due` | в момент срока |
| `overdue` | если срок прошёл и задача не закрыта, повтор `nag_interval` |
| `postpone_followup` | через `postpone_recheck` после переноса |

Каналы доставки задаются в конфиге (`notify.channels`) и включают `console`,
`file` (JSON-строки в `ordo-outbox.jsonl`), `telegram`, `email`, `none`.
Можно указать несколько — сообщение уйдёт во все.

### Пример: проверка раз в 30 минут через cron

```cron
*/30 * * * * cd /path/to/project && ORDO_NOTIFY=telegram /usr/bin/python3 -m ordo remind
```

### Telegram

Без сторонних библиотек (через public Bot API). Достаточно задать:

```bash
export ORDO_TELEGRAM_TOKEN="123456:ABC..."
export ORDO_TELEGRAM_CHAT="123456789"
export ORDO_NOTIFY="telegram"      # или "telegram,console"
```

`ORDO_TELEGRAM_CHAT` — ваш числовой id (узнать можно у `@userinfobot`); он же
служит allowlist для бота: сообщения из других чатов игнорируются.

### Telegram-бот: команды в чате

`ordo` умеет не только отправлять, но и **принимать** команды. Демона нет —
как и напоминания, бот запускается командой (из cron, systemd или GitHub
Actions) и обрабатывает накопившиеся сообщения:

```bash
ordo bot --test      # отправить проверочное сообщение -> видно, что токен и чат верные
ordo bot --once      # обработать очередь апдейтов и выйти (для cron)
ordo bot --follow    # long-poll и живой диалог (локально, Ctrl+C — стоп)
```

В чате работают те же команды, что и в CLI (весь CLI Ordo прокидывается как есть):

| Команда | Что делает |
|---|---|
| `/start`, `/help` | приветствие и справка |
| `/check` | что требует внимания |
| `/list [--all] [--overdue]` | список задач |
| `/add "текст" -d 3d -P 1` | новая задача |
| `/show <id>` | подробности задачи |
| `/start <id>` | взять в работу |
| `/done <id> [-c текст]` | закрыть задачу |
| `/block <id> [-c текст]` | заблокировать |
| `/comment <id> текст` | комментарий |
| `/postpone <id> -d 5d -r причина` | перенести срок |

Полезные флаги: `--dry-run` (показать ответы, ничего не отправляя),
`--allow-chat ID` (ограничить доступ одним чатом), `--limit N`.

Смещение обработанных апдейтов (`offset`) хранится в БД (`meta`, ключ
`bot.telegram.offset`), поэтому повторный запуск не отвечает на одно и то же
сообщение дважды.


## Конфиг

`ordo config` печатает текущие значения, `ordo config --example` кладёт
starter-файл в `~/.config/ordo/config.json` (или `$ORDO_CONFIG`).
Приоритет: значения по умолчанию → файл → переменные окружения.

```json
{
  "db": "ordo.db",
  "due_time": "18:00",
  "reminders": {
    "before": "1d",
    "nag_interval": "12h",
    "postpone_recheck": "1d"
  },
  "notify": { "channels": ["console"] }
}
```

## Структура

```
ordo/
├── ordo/
│   ├── cli.py         # команды и разбор аргументов
│   ├── service.py     # бизнес-логика (Store): задачи, переносы, история
│   ├── reminders.py   # поиск и отправка напоминаний
│   ├── bot.py         # Telegram-бот: приём апдейтов и ответы
│   ├── command.py     # разбор текста в команду CLI (бот и IssueOps)
│   ├── report.py      # таблицы и цвета
│   ├── timeparse.py   # разбор «3d», «2026-11-30», «tomorrow 18:00»
│   ├── models.py      # датаклассы
│   ├── db.py          # схема SQLite
│   ├── config.py      # конфиг: файл + окружение
│   └── notify/        # каналы: console, file, telegram, email
└── tests/             # unittest, без внешних зависимостей
```

## Что дальше (roadmap)

1. **Telegram-бот как второй интерфейс.** Сделано: `ordo bot` принимает
   `getUpdates`, выполняет те же команды, что и CLI, и отвечает в чат
   (`--once` для cron, `--follow` локально, `--test` для проверки). Дальше —
   реестр репозиториев.
2. **Систематизация репозиториев.** Реестр проектов с адресами и статусом,
   задачи с привязкой к репозиториям, отчёт «где давно ничего не делалось».
3. **Агенты.** Несколько агентов под разные задачи (разбор кода, ревью, документация),
   с приоритизацией через `ordo check`.
4. **Веб-панель** поверх той же схемы БД, когда CLI станет тесно.
