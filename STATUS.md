Короткая точка входа для нового диалога (человека или агента).

## Что это

`Ordo` — планировщик задач со сроками, историей, комментариями и напоминаниями.
Чистая стандартная библиотека Python 3.9+ (SQLite, `argparse`, `smtplib`, `urllib`),
без внешних зависимостей. Версия `0.1.0`.

Задуман как фундамент системы: сначала порядок в своих задачах и репозиториях,
потом сверху — Telegram-бот, реестр репозиториев и агенты.

## Что сделано

- **Хранилище (SQLite):** `projects`, `tasks`, `comments`, `events`, `reminders`.
  Все времена — UTC ISO-8601 (`…Z`), поэтому сортировка строкой корректна.
- **Задачи:** срок, приоритет `P0..P3` (можно словами `critical/high/normal/low`),
  статусы `todo / doing / blocked / done / cancelled`.
- **Комментарии** по ходу работы с типом (`note/progress/blocker/review`).
- **История:** отдельная таблица `events` — создание, смена статуса, переносы,
  комментарии, отправленные напоминания. Смотрится через `ordo show <id>`.
- **Перенос срока с напоминанием:** `ordo postpone <id> -d <когда> -r "<причина>"`.
  Увеличивает `postpone_count`, пишет событие в историю, сохраняет причину
  комментарием, пересобирает напоминания и ставит догон `postpone_followup`.
- **Напоминания:** `due_soon` / `due` / `overdue` (повтор) / `postpone_followup`.
  Отправка — командой `ordo remind` (одноразово, для cron), не фоновым демоном.
- **Telegram-бот:** `ordo bot` умеет не только слать, но и **принимать** команды
  (`getUpdates`). Режимы: `--once` (очередь апдейтов для cron — так он работает
  из GitHub Actions), `--follow` (long-poll локально), `--test` (проверочное
  сообщение), `--dry-run`. В чате работает весь CLI (`/add`, `/list`, `/done`,
  `/postpone`, ...); смещение обработанных апдейтов хранится в `meta`
  (`bot.telegram.offset`), доступ ограничивается `chat_id`.
- **Каналы доставки** (`notify/`): `console`, `file` (JSON-lines в outbox),
  `telegram`, `email`, `none`. Telegram и SMTP — на stdlib, без библиотек.
- **Отчёт `ordo check`:** OVERDUE / DUE TODAY / DUE SOON / POSTPONED / BLOCKED / STALLED.
- **CLI:** `init, project, add, list, show, edit, rm, start, block, done, cancel, reopen,
  comment, postpone, check, remind, bot, history, log, config`. Есть `--json` для машин.
- **Тесты:** 58 unittest-тестов (`tests/`), покрывают парсинг времени, логику Store,
  напоминания, CLI, бота и хелперы хостинга.

## Ключевые решения (и почему так)

1. **Только stdlib.** Никаких зависимостей: чтобы проект жил годами и запускался
   где угодно без `pip`. Telegram/почта сделаны на `urllib`/`smtplib`.
2. **`ordo remind` — отдельная команда, а не демон.** Прозрачно, тестируемо,
   одинаково работает из cron, systemd-таймера и (позже) из бота.
   Логика отделена от CLI: любой другой интерфейс дёргает тот же `Store`.
3. **Напоминания — это outbox (таблица `reminders`), а не «магия» на лету.**
   Понятно, что запланировано, что отправлено, что упало (`attempts`, `last_error`).
4. **Повтор просрочки не спамит:** после отправки сразу ставится следующее
   напоминание через `reminders.nag_interval` (по умолчанию 12 ч).

## Известные ограничения / не проверено

- **Telegram вживую не проверялся с настоящим токеном** (токена у агента нет).
  Проверено: `ordo bot --once` против локального fake-API (приём апдейта → ответ
  в тот же чат → задача в БД → повторный прогон не дублирует), юнит-тесты без
  сети. Первый реальный прогон — `ordo bot --test` и `ordo bot --once` за тобой.
- **SMTP вживую не проверялся** (не было ящика). Код есть, первый прогон — за тобой.
- Бот в GitHub Actions опрашивает Telegram по cron (минимум 5 минут) — задержка
  ответа до одного интервала; мгновенный вебхук требует внешнего сервера.
- Нет повторяющихся задач по расписанию (только дата/интервал от «сейчас»).
- Один файл БД на папку; мультипользовательности нет (и не требуется).
- Демо-база из прошлого запуска лежала в `/tmp/opencode/ordo-demo` — она **временная**,
  после перезагрузки может исчезнуть. Это была демонстрация, не рабочие данные.

## Размещение в облаке (бесплатно, без карты)

Разбор вариантов — в `HOSTING.md`. Коротко:

- **Вариант A (рекомендуемый): GitHub Actions как сервер.** Код на Python
  работает как есть, `ordo remind` крутится по расписанию, состояние `ordo.db`
  коммитится назад, дашборд — на GitHub Pages, управление — через issue.
- **Вариант B: Cloudflare Workers (Python GA) + D1 + Cron Triggers.** Почти как
  есть, но `db.py`/`config.py` меняются под D1 и `env`.

PythonAnywhere free больше не подходит (нет scheduled tasks для новых аккаунтов).
